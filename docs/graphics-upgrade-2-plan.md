# 画面のリッチさ改善 第2弾：CHASE と FPV の「映像らしさ」

## Context
第1弾（`83eacee`、PR #6）で描画コール数はポーズにより約 3〜10 分の 1 に減り、海・空・地形・機体の見た目も改善した。ただし CHASE 視点は、ほぼ素の 3D 描画のままでまだ物足りない。FPV 視点も、レンズの歪み・色ずれ・ノイズ程度で、実機の FPV ゴーグル映像らしさが足りない。

ユーザーの選択は次のとおり：
- CHASE 視点：FPV モードのようなアナログ感、カメラの動き、光の表現、空気感と奥行き、機体まわりの演出（全項目）
- FPV らしさ：FPV 視点と CHASE 視点の両方

方針：
- 第1弾で下げた負荷を食いつぶさないよう、効果はできるだけ既存の 1 本のポストパスにまとめる。
- 追加するのは feed の mip 生成と 1×1 の露出パスだけにする。
- 品質レベル（`render-quality.mjs`）に効果の段階を連動させる。
- 「動きを減らす」設定では、揺れ・ジェロ・モーションブラーを止める。

## Phase 0：計画を docs に書き出す
- この計画を `docs/graphics-upgrade-2-plan.md` に保存してから着手する。
- 比較用のベースラインとして、現状 `83eacee` のスクリーンショットと capture を、既存の CDP ハーネス（固定ポーズ）で取得する。

## Phase 1：ポスト処理の土台
- 新規 `dist/feed-post.mjs`：`main.mjs` に直書きしているポストシェーダをモジュールへ移す。処理の順序は今の契約を保つ：
  1. linear 空間での効果
  2. `colorspace_fragment`
  3. 表示空間でのアナログ処理
  4. brightness
- feed target（`render-color.mjs` の `createFlightRenderTarget`）で `generateMipmaps` を有効にし、`LinearMipmapLinear` にする。mip はブルーム・被写界深度・モーションブラーの低コストなぼかし源として使う（追加のぼかしパスは作らない）。
- 逆 Z のときは、Phase 1 で付けた float の `DepthTexture` をポストシェーダから読む。log 深度にフォールバックした端末では、深度を使う効果を無効にする。
- 露出の自動調整：1×1 の HalfFloat ピンポンを用意する。feed の最小 mip から平均輝度を取り、前フレームの値と時定数でなめらかに追従させる。1 ピクセルなので負荷は無視できる。

## Phase 2：光の表現（両視点）
- **ブルーム**：mip 3〜5 の明部を、しきい値付きで足す。対象は空の太陽まわり、水面のグリント、LED。
- **太陽**：グレアと、レンズフレアのゴースト（太陽からスクリーン中心を結ぶ線上に数個）を出す。
  - 太陽の画面位置は CPU で計算して uniform で渡す。
  - 遮蔽は太陽位置まわりの深度サンプルで判定する（深度がない端末は輝度で代用）。
- **グレーディング**：露出は 1×1 パスの平均輝度で決める。
  - FPV：ゴーグル風に彩度とコントラストを強め、暗部に少し青を寄せる。
  - CHASE：シネマ風のやわらかいトーンカーブ。

## Phase 3：空気感と奥行き
- **CHASE の被写界深度**：深度と機体までの距離（約 0.9 m）から CoC（ぼけの大きさ）を求め、mip を補間する。背景と手前の地面を少しぼかし、小さな機体に視線が集まるようにする。
- **モーションブラー**：実速度とカメラの角速度から方向を決め、mip 1 から 4〜6 タップでぼかす。
  - FPV：前進方向への放射状。
  - CHASE：カメラの移動方向。
- 20 倍の高速移動のときだけ強く効かせ、低速では残らないようにする。

## Phase 4：アナログ映像（両視点）
- **FPV**：既存のアナログ映像処理（歪み・色ずれ・ソフトニング・グレイン・走査線・ビネット）を保ったうえで、次を足す。
  - ジェロ：角速度と振動からローリングシャッター風に、走査線ごとに横へずらす。
  - 露出のふらつきとホワイトバランスの揺らぎ：空を向くと暗く寄る。
  - 受信状態の劣化：home からの距離と、home と機体の間の遮蔽（`segmentHitsSolid`）に応じて、ノイズの帯・同期の乱れ・色抜け・一瞬のブラックアウトを出す。近距離ではほとんど出さない。
- **CHASE**：FPV と同じ処理を、強さ約 60%、レンズ歪みは弱め、ビネットは控えめにして重ねる。CHASE の映像出力を「2 台目のアナログカメラ」として扱う。
- 既存テストの固定値（`test-fpv-signal` / `test-chase-signal` の定数・シェーダハッシュ・「CHASE にビネットなし」）は、ユーザーの要望による意図した変更として新しい契約に書き換える。

## Phase 5：カメラの動き
- **`chase-camera.mjs`**：
  - 速度に応じて FOV を伸縮する（72→最大 82°、なめらかに追従）。
  - 機体のバンクを 15% だけ追従させる。
  - プロペラの微振動と、低空での乱流によるカメラの揺れを加える。
  - 加減速の追従遅れは既存の上限を保つ。
- **FPV**：カメラの姿勢に高周波の微振動と乱流を加える。乱流は低空・高速ほど強くする。
- **FPV でダクトとプロペラを映す**：FPV でも機体の一部を描く。ベイク後のダクトのメッシュとプロペラのグループだけ表示し、キャノピーやカメラなど、カメラに干渉する部品は隠す。プロペラが回るとブラーのディスクが画面の下端に見える。
- 「動きを減らす」設定では、FOV の伸縮・揺れ・ジェロを止める。

## Phase 6：機体まわりの演出
- **LED**：機体の下面に LED ストリップを付ける（機種色の emissive。ブルームで光る）。
- **砂ぼこり**：地面すれすれ（クリアランス 1.2 m 未満）で、プロペラの吹き下ろしによる砂ぼこりの粒子を出す。
  - 最大約 200 個の Points で、地表の素材に応じて色を変える（アスファルト・草地・砂）。
  - 水上では既存の波紋を使う。
- **接地影**：影マップの範囲外の高度（40〜150 m）でも高度が分かるよう、機体の真下にやわらかい丸い影を落とす。地形の法線に沿わせた 1 枚の板にする。

## Phase 7：品質連動・テスト・ドキュメント
- `QUALITY_LEVELS` に `bloom` / `dof` / `motionTaps` / `flare` を追加し、低い段階から順に切る。low ではブルームを弱め、被写界深度とモーションブラーは切る。
- 新規テスト（いずれも CPU 側で確認できる範囲）：
  - ポストシェーダの処理順序と各効果の有無
  - 露出の追従と、動きを減らす設定
  - CHASE の FOV・揺れの上限
  - 受信劣化の距離と遮蔽のモデル
  - 粒子の発生条件
- 既存テストのうち意図して変える固定値を更新する：
  - `test-chase-signal`、`test-fpv-signal`、`test-render-color`、`test-ground-output`（ポスト処理の順序の文言）
  - `test-chase-camera`（FOV の伸縮）
- `docs/render-performance.md` に前後の数値と画像比較を追記し、README にも追記する。

## 主な変更ファイル
- 新規：`dist/feed-post.mjs`、`dist/exposure.mjs`（1×1 の露出パス）、`dist/camera-motion.mjs`（揺れ・乱流・FOV）、`dist/signal-model.mjs`（受信劣化）、`dist/airframe-effects.mjs`（LED・砂ぼこり・接地影）

## 検証
- 各 Phase の後に `npm test && npm run check`。
- ヘッドレス Chrome の CDP ハーネスで、固定ポーズの FPV / CHASE を `83eacee` と比べる。見るのは次の 3 点：
  - スクリーンショット
  - 描画コール（ポスト以外が増えていないこと）
  - 実飛行 60 Hz でのコストと P95
- 太陽を向いたポーズ、遠距離のポーズ、遮蔽物の陰、低空ホバー（砂ぼこり）、高速移動（モーションブラー）を追加して確認する。
- スマホ相当の画面と `?quality=low` で、効果がきちんと間引かれることを確認する。
- iPhone 実機での FPS と見た目は、環境上こちらでは確認できない。
